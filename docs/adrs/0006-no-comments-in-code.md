# ADR 0006 – No Comments in Code, Estate-Wide

* **Status**: Accepted
* **Deciders**: Ryan Grippeling
* **Date**: 2026-09-04
* **Tags**: Engineering::CodeStandards, DX, Knowledge, SupplyChain
* **Version**: 1.0.0

---

## Context and Problem Statement

A comment is a claim about code that no tool checks. It is written once, reviewed once, and then
drifts, because nothing fails when it stops being true. The estate has the better instruments
already: a precise name, a type, a smaller function, a test that states the case, and — for
anything that outlives a single expression — a document that is reviewed, linked and kept current.

The rule was adopted and proven in `webgrip/twente.dev`. Commit `c0fbb26` removed **2.687 lines
across 126 files**, tokenised per language, with every TypeScript file verified by printing both
ASTs with `removeComments` and demanding byte equality. The result held: the site builds, deploys
and passes its gates unchanged.

That same rollout produced the two failures this record exists to prevent.

**Knowledge was destroyed, measurably.** Three wrangler lessons lived in `wrangler.toml`. Two
survived only because they had coincidentally been written into `AGENTS.md` and the README the day
before. The third is gone: *why the apex is bound with a `route` rather than `custom_domain = true`*
— a custom domain has Cloudflare create the DNS record itself and refuses while a stale proxied
A-record is present, which is precisely the situation in which you need it. No grep over `docs/`,
the ADRs or the README finds that reason today.

**The sweep broke a generator.** It removed the `BEGIN`/`END` markers from `ops/docker/web/nginx.conf`,
`gen:ops --check` failed, and container parity was red on `main` until `8a7566a`. Those markers are
machine-read syntax, exactly like `# syntax=`. They belonged on the allowlist and were not on it.

**And the rule does not hold itself up.** A prose comment re-entered twente.dev at
`src/components/NewsletterForm.astro:130` in commit `dd7f0d1`, the same day as the strip. A rule
written only in a markdown file is a suggestion.

What remains is **24.363 comment lines across fourteen repos**, roughly 70% of it in
`homelab-cluster` and `ploeg` — the two repos where a wrong edit costs a cluster or a release train.
The cheap repos are not where the value is, and the valuable repos are not where you want to be
learning. A survey of all fifteen repos, verified against the files, found five classes that a
naive sweep deletes silently:

1. **Parseability is not a classifier.** 96% of the estate's YAML comments (12.215 of 12.721) and
   58% of shell parse cleanly as YAML and bash respectively. Prose in a whitespace-tolerant language
   is indistinguishable from commented-out code by parsing alone.
2. **Renovate annotations sit on more anchors than expected** — `tag:`, `repository:` + `tag:`,
   `version:`, `image:`, `talosVersion:`, `kubernetesVersion:`. An allowlist that knows only `ARG`
   strips them, and the Talos installer, kubelet, buildkit, kepler, kroki, grafana and ploegd go
   silently unmanaged.
3. **Some comments are a mechanism.** Nine Dockerfiles in `webgrip/infrastructure` carried
   *Release re-entry touch* lines whose existence was the function: a no-op diff that made a
   push-diff release matrix re-enter. (This one resolved itself — see the decision below.)
4. **Vendored licence blocks.** Seven files under `erfbeeld/apps/backend/public/js/filament/` carry
   `@license` and `/*!` blocks in browser-served bundles, generated by a composer hook, committed,
   and marked nowhere. Stripping them is a licence breach with a green verification underneath it.
5. **Doc-comment forms are read by toolchains.** `go doc`, rustdoc doctests and PHPStan all consume
   comment syntax as input.

## Decision Drivers

| # | Driver (why this matters) |
| - | ------------------------- |
| 1 | Intent must live where something checks it: a name, a type, a test, or a reviewed document |
| 2 | Knowledge must be moved before it is deleted — the destruction above must not repeat |
| 3 | Machine-read directives are syntax and must survive, including the ones nobody enumerated |
| 4 | The rule must be enforced by a gate, not by discipline; it has already been broken once |
| 5 | A repo must be able to stop the bleeding before its tree is clean |
| 6 | The two highest-risk repos must be last, and must benefit from everything learned before them |

## Considered Options

1. **The rule in each `AGENTS.md`, enforced by review** — the status quo.
2. **The rule as a ratified decision, a shared tool gating the delta in every repo, and a staged
   per-repo strip behind a ledger.**
3. **A single estate-wide sweep**, one tool run, all fifteen repos.
4. **Abandon the rule** and keep comments as an accepted practice.

## Decision Outcome

### Chosen Option

**Option 2.** The rule is estate-wide and binding. Its enforcement is a shared CLI,
`@webgrip/comment-ban`, and its rollout is staged per repo, cheapest first.

### Rationale

Option 1 is what we have, and the violation on the day of the strip is its refutation. Option 3 is
the version that already destroyed knowledge once, at 2.687 lines; at 24.363 lines across repos
that run a Kubernetes cluster and the release trains, the same process would fail at roughly ten
times the scale, and the survey found five specific mechanisms by which it would. Option 4 discards
a rule that measurably improved the one repo that adopted it.

The load-bearing distinction in Option 2 is that **the delta and the tree are separate problems**.
A gate on newly changed files can be switched on in a repo months before that repo is clean, which
stops the bleeding immediately and makes every later strip smaller. A gate on the whole tree can
only follow a strip. Treating them as one thing is what forces the big-bang sweep.

### The rule

> Comments are NOT allowed. Always communicate intent with code: a precise name, a type, a smaller
> function, a test that states the case. A comment is a failure. This holds for every language in
> the repo, prose in YAML and TOML included. Machine-read directives stay, because the toolchain
> acts on them as syntax. Anything that outlives a single expression belongs in `docs/` or an ADR,
> where it gets reviewed, linked and kept current.

### What is not a comment

These forms are input to a toolchain. They are syntax, and they stay:

| Class | Form |
| ----- | ---- |
| Shebang | `#!` |
| Dockerfile frontend | `# syntax=` |
| Schema hint | `# yaml-language-server: $schema=` (315 occurrences in `homelab-cluster` alone) |
| Renovate | `# renovate: datasource=…`, valid **only** on the line immediately above its key |
| TypeScript / lint | `@ts-check`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `eslint-disable`, `eslint-enable`, `prettier-ignore`, `@vite-ignore`, `webpackIgnore` |
| Markup | `<!-- prettier-ignore -->` |
| Shell | `# shellcheck` |
| Python | `# noqa`, `# pragma:`, `# type:` |
| Go | `//go:build`, `//go:generate`, `//go:embed`, `//nolint` |
| Lua language server | `---@type`, `---@param`, `---@return` |
| **Doc comments** | godoc directly above an exported identifier; rustdoc `///` and `//!`; PHPDoc blocks carrying a type tag (`@var @param @return @template @phpstan-* @psalm-* @mixin @property @method`) |
| Generator markers | registered per repo in that repo's `.comment-ban.json` |
| Vendored | any path where `git check-attr` reports `linguist-vendored` or `linguist-generated` |

The doc-comment row is a decision, not an omission: `go doc`, rustdoc doctests and PHPStan read
these forms as input, which is the same exemption the rule already grants `# syntax=`. Narrative
prose inside a function body is not a doc comment and goes.

The allowlist is **a datafile in the tool**, extended per repo by `.comment-ban.json`. It is never a
judgement made at strip time. A generator marker that is not registered **fails the check** rather
than disappearing quietly — that is the direct lesson of `8a7566a`.

### Enforcement

`@webgrip/comment-ban` ships four modes: `--report` (a block-level ledger), `--check` (delta by
default, `--all` for the tree), `--write` (strip, with a per-language proof), and
`--audit-directives`, which finds pins **missing** an annotation and annotations detached from their
key. That last mode exists because a tool that only protects the directives already present is
blind to the failure that matters most; it already has two confirmed findings, `RUNNER_VERSION` in
`infrastructure/ops/docker/ci-runner/Dockerfile:3` and the annotation at
`homelab-cluster/talos/talenv.yaml:2` that sits thirteen lines above its key and is therefore
invisible to Renovate.

`--write` **refuses to run** while the target repo's ledger holds undecided entries. Reporting and
moving knowledge come first, stripping second; that ordering is the specification produced by the
lost wrangler rationale, expressed as code rather than as good intentions.

There is deliberately **no scheduled estate-wide report**. Where the delta gate is on, the count of
new comments is zero by construction, and a dashboard for a structurally-zero number is not a
control. An on-demand sweep covers the repos that do not yet have the gate.

### Rollout order

Ascending stakes: `renovate-config`, `claude-config`, `frontend-toolkit`, `semantic-release-config`,
`webgrip-ai-skills`, `backstage-application`, `webgrip.nl`, `erfbeeld`, `infrastructure`,
`workflows`, `ploeg`, `homelab-cluster`. The last two begin only once the first ten have produced
no surprises. `twente.dev` is already done.

### Positive Consequences

* Intent moves to the places that are checked: names, types, tests, and documents under review.
* Every repo can reject new comments immediately, independent of when its tree gets cleaned.
* The allowlist becomes an explicit, tested, shared artifact rather than tribal knowledge — the
  estate has never before had a written list of which comment forms are load-bearing.
* `--audit-directives` closes a supply-chain gap that predates this decision: pins that were never
  under Renovate at all.
* Knowledge that was previously buried in a config file lands in `docs/` and ADRs, where it is
  linked and reviewed.

### Negative Consequences / Trade-offs

* The knowledge migration is real work and cannot be automated. A person decides, per block, between
  docs, an ADR, and deletion. This is the dominant cost of the whole programme.
* Several repos have no `docs/adrs/` yet, so their first strip is gated on bootstrapping a
  destination.
* Some languages have no strong equivalence proof available in Node. Rust, Dockerfiles, nginx
  configs, CSS and Markdown are stripped in their own commits so a breakage bisects to one class.
* A shared allowlist is a shared failure mode: a gap in it is a gap in twelve repos at once.
* Reading unfamiliar code gets harder before it gets easier, during the window where the narrative
  is gone and the document has not yet been written.

### Risks & Mitigations

* **A directive is stripped.** Mitigated by fixtures drawn from the real estate for every class
  above, and by the rule that an unregistered marker fails rather than vanishes. One confirmed false
  negative anywhere halts the rollout until that class is a fixture and the tool has cut a patch.
* **A vendored licence block is stripped.** Mitigated by `git check-attr`; `erfbeeld` gains
  `linguist-vendored` on the filament paths before its first report run.
* **The template sync overwrites CI configs.** `sync-template-files.yml` lists three workflow files
  in `FILES_TO_SYNC` with overwrite semantics, and in this repo `on_source_change.yml` is the repo's
  own self-CI, not a consumer template. It is harmless only because no caller exists. Fixing that
  list is a precondition of scheduling it.
* **Two-tree drift in this repo.** `.forgejo/` is generated from `.github/` by a path rewrite, so
  both trees are stripped in one commit and the generator re-run; `forgejo-parity-check.sh` moves
  into this repo's self-CI first, which ADR 0002 already claims happens.
* **Knowledge is lost anyway** because a reviewer waves the ledger through. Mitigated by reviewing
  the moved-to-dropped ratio per repo: thousands dropped and nothing moved is the signal that nobody
  read it.

## Validation

* **Immediate proof** — `comment-ban --report` against `twente.dev` returns exactly one item,
  `src/components/NewsletterForm.astro:130`, the violation that re-entered after the strip. The tool
  passes its own `--check --all`: it contains no comments.
* **Ongoing guardrail** — every repo's `on_source_change` runs `--check` on the delta, so a new
  comment fails the push that introduces it. This is the monitor; there is no separate dashboard.
* **Per-repo closure** — a repo is done when its ledger is fully decided, its `--write` proof is
  green, its own gates are green, and `--check --all` is switched on. A clean tree without the gate
  does not count.

## Compliance, Security & Privacy Impact

Net positive, in two specific ways. Renovate annotations become a protected, tested class instead of
incidental text, and `--audit-directives` surfaces pins that were never managed at all — two are
already confirmed. Vendored licence blocks become protected by a git attribute rather than by
nobody having touched them yet. No data classification changes; no secret material is involved.
Removing prose from configuration slightly reduces the surface on which credentials have
historically been described in passing, but that is not the purpose and is not claimed as a control.
